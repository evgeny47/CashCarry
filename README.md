# CashCarry

Cash-and-carry для Финам: лонг акции + шорт фьючерса на тот же актив, несколько пар на одном счёте (.NET 8).

## Проекты

| Проект | Назначение | Статус |
|---|---|---|
| `CashCarry.Core` | Инструменты, базис, комиссии, дивиденды, позиция, стратегия, интерфейс `IBrokerGateway` | готов |
| `CashCarry.Risk` | `PairExecutor` (исполнение с контролем ноги), `MarginGuard`, `HedgeMonitor`, `KillSwitch`, `TradingSchedule` | готов |
| `CashCarry.Broker.Finam` | gRPC Finam Trade API: JWT по секрету, заявки, счёт, котировки, диагностика | готов, не проверен на реальном счёте |
| `CashCarry.Broker.Paper` | Симулятор: лимитные заявки, объём стакана, ГО, ВМ, клиринг, инъекция отказов | готов |
| `CashCarry.Engine` | Движок робота: главный цикл по парам (`RobotWorker`), настройки, SQLite, источники цен для Paper | готов |
| `CashCarry.Host` | Запуск робота: конфигурация, Serilog, команды `--finam-check`, `--find-symbols`, `--reset-kill-switch` | готов (режим Paper) |
| `CashCarry.Backtest` | Тестер: загрузка свечей Финам в SQLite и прогон того же `RobotWorker` на истории | готов |

## Модель

Единица пары = 1 контракт против K акций (SR: K = 100 акций SBER).

Пары задаются списком `Pairs` в `appsettings.json`: у каждой свои акция, фьючерсы, дивиденды, позиция и
необязательные переопределения секции `Strategy`. Деньги счёта и kill switch общие.

- Базис входа: `F_bid × PV − S_ask × K`; базис выхода: `F_ask × PV − S_bid × K`.
- PnL без комиссий = `B_вход − B_выход` (проверяется тестом).
- Капитал на единицу = `S × K + комиссия + ГО`. Доходность = `прибыль / капитал × 365 / дни`.

Решения (`CashAndCarryStrategy.Evaluate`):

- **Вход** — базис входа + дивиденды до экспирации (после налога) − комиссии туда-обратно ≥ `MinEntryAnnualYield`.
  Если до ближнего контракта меньше `MinDaysToExpiryForEntry` дней — входим в следующий.
- **Досрочный выход** (`Early`/`Both`) — чистый PnL ≥ `EarlyExitMinProfitPerUnit` и оставшийся базис
  + дивиденды впереди дают < `MinHoldAnnualYield`.
- **У экспирации** (≤ `RollWindowDays`) — перенос, если календарный спред − 3 фьючерсные комиссии
  ≥ `MinRollAnnualYield`; иначе закрытие. В режиме `Early` — всегда закрытие.

## Исполнение и риск

- Заявки — «агрессивные лимиты» (лучшая цена ± `MaxSlippage`), таймаут, снятие, повтор на остаток.
- Вход/выход: сначала акция, затем фьючерс на исполненное число целых единиц; лишние лоты сразу
  откатываются. Откат не удался → `Broken` + kill switch.
- Перенос — всё или ничего: при сбое возвращаемся к шорту ближнего контракта.
- Kill switch блокирует вход и перенос, но не закрытие.
- `MarginGuard`: при входе оставляет резерв свободных денег под вариационную маржу (`VariationMarginReserve`
  от номинала шорта): при росте акции фьючерс платит ВМ деньгами каждый клиринг.
- `TradingSchedule.MoexMainSession`: 10:05–13:55 и 14:10–18:35 МСК, без выходных и праздников.
- `HedgeMonitor`: сверка позиций брокера с учётом робота; N расхождений подряд → kill switch.
  Предполагается, что акции и фьючерсы всех пар на счёте принадлежат только роботу; один символ — только в одной паре.
- Резерв под ВМ считается по всем парам: `MarginGuard.MaxUnitsToOpen` учитывает резерв остальных пар.
- `Robot:MaxCapital` — общий лимит денег робота (акции по цене входа + ГО + резерв ВМ). Ограничивает только новые входы.

## Запуск

Подробная инструкция для пользователя, включая подключение к Финам: [docs/ИНСТРУКЦИЯ.md](docs/ИНСТРУКЦИЯ.md).


Быстрая симуляция (окружение Development: тик раз в секунду, синтетические цены, круглосуточно, база `cashcarry-dev.db`):

```bash
dotnet run --project src/CashCarry.Host
```

Боевое расписание MOEX (окружение Production: тик 15 с (лимит запросов Финам на 7 пар), только 10:05–13:55 и 14:10–18:35 МСК):

```bash
dotnet run --project src/CashCarry.Host --launch-profile Production
```

Остановка — Ctrl+C. Позиция, kill switch и журнал операций хранятся в SQLite и переживают перезапуск.

- Настройки: `src/CashCarry.Host/appsettings.json` (поверх него в Development — `appsettings.Development.json`).
- Логи: `src/CashCarry.Host/bin/Debug/net8.0/logs/`, база: `.../net8.0/data/`.
- Kill switch сбрасывается только вручную, после разбора причины (для боевой базы добавьте `--launch-profile Production`):
  `dotnet run --project src/CashCarry.Host -- --reset-kill-switch`

Каждый тик: котировки → по каждой паре сверка позиций и решение стратегии → общая проверка ГО → исполнение
(сначала выходы и переносы, затем входы по убыванию доходности) → запись в базу. Ошибка одной пары не
останавливает остальные. Позиции хранятся по имени пары; старая база одиночной пары переносится при запуске.
При смене дня начисляются дивиденды, у которых прошёл последний день покупки.

## Тестер на истории

`CashCarry.Backtest` прогоняет **тот же** `RobotWorker` (стратегия, исполнитель, ГО, лимит капитала) на свечах:
котировки подаёт `HistoricalFeed` (цена известна только после закрытия свечи, спред достраивается к close),
брокер — `PaperBroker`, время — `BacktestClock`. Тик — закрытие каждой свечи любого инструмента.

```bash
dotnet run --project src/CashCarry.Backtest -- download --from 2026-07-01 --pairs all
dotnet run --project src/CashCarry.Backtest -- run --from 2026-07-01 --pairs SBER
```

- Пары, стратегия, комиссии, риск — из `src/CashCarry.Host/appsettings.json`; свои настройки — `src/CashCarry.Backtest/backtest.json`.
- Свечи: `src/CashCarry.Backtest/bin/Debug/net8.0/data/history.db`, отчёты прогонов: `.../data/backtest/<время>/`.
- Истёкшие квартальные серии дописываются автоматически (третий четверг, ГО ближайшей настроенной серии).
- Тестер не ссылается на `CashCarry.Host`, поэтому собирается, пока робот запущен.
